   ～manabaから課題を自動で取ってくるDiscord Botを作ろう～
================================================================
対象：Pythonの基本は分かるが、このBotは自分で書き直しながら理解したい人
目標：manaba_bot.py を「意味を説明できる状態」で自分の手で書き上げる

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  はじめに ― このBotはどんな仕組みで動くの？
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

前回(手入力版)との違いは「課題をmanabaから自動で取ってくる」点です。

  ① 30分おきに、プログラムがmanabaにログインする
        ↓
  ② 「未提出課題」の一覧ページを読み取る(小テスト/アンケート/レポート)
        ↓
  ③ 前回と比べて、新しい課題・締切の変更・提出済みを判定してDBに保存
        ↓
  ④ 新しい課題や締切の変更があれば、Discordのチャンネルに通知
        ↓
  ⑤ 5分おきに「リマインドすべき課題」を確認して、まとめて通知
        ↓
  ⑥ スラッシュコマンド(/tasks /done /add ...)で、いつでも操作できる

ファイルは基本的にこれだけです：

  manaba_bot.py     Botの本体(1ファイルに全部入っています)
  requirements.txt  必要なライブラリの一覧
  .env              トークンやパスワード(自分で作る。絶対に公開しない)
  .gitignore        .env などをGitHubに上げないための設定
  tasks.db          課題のデータ(Botを動かすと自動で作られる)

前回の指導書との違い：
  ・database.py と bot.py に分けず、1ファイル(manaba_bot.py)にしています
  ・課題は /task のポップアップ入力ではなく、manabaから自動取得します
    (manabaにない予定のために /add コマンドは残しています)
  ・時刻はUTCではなく日本時間(JST)で扱います
  ・Developer Portalの特権インテント(MESSAGE CONTENT など)は不要です

【大事な注意①】動作確認の範囲について
  このコードは、manabaによく似た「模擬サーバー」と43個の自動テストで
  動作を確認しています。ただし、本物の千葉工大manabaには、まだ接続して
  いません。必ず最初に「python manaba_bot.py --check」で、本物の画面から
  課題が正しく取れるか確認してください。うまく取れない場合の直し方は、
  付録Bにあります。

【大事な注意②】manabaの画面を読み取る仕組みについて
  manabaには、私の知る限り公式の公開APIがありません。そこでこのBotは
  「人がブラウザでやる操作(ログイン→一覧を開く)」をプログラムで
  代行します。学内の利用規約・情報セキュリティのルールに反しないよう、
  個人利用の範囲で使ってください。また、ID/パスワードは自分のPCの
  .env にだけ置き、他人に渡したり、公開したりしないでください。

─────────────────────────────────────────
  0-2. フォルダを作って VS Code で開く

好きな場所に「manaba-reminder-bot」というフォルダを作り、
VS Code で「ファイル → フォルダーを開く」から開きます。

  │ が見つけられません。プロジェクトごとにフォルダを分け │

  └──────────────────────────────────────────────────────┘
  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ 「python manaba_bot.py」と打つだけで、同じフォルダの │

─────────────────────────────────────────
  0-3. 仮想環境(venv)を作る
─────────────────────────────────────────

VS Code のターミナルで、フォルダを開いたまま順に実行：

    python -m venv venv
    venv\Scripts\activate

(PowerShell で「スクリプトの実行が無効」と出たら、コマンドプロンプトを
 使うか、先に次を1回だけ実行：
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned )

行の先頭に「(venv)」と付けば成功です。

VS Code の下のほうに Python のバージョンが表示されている部分があります。
そこをクリックして、「venv」と書かれたインタプリタを選んでください。

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ pip で入れたライブラリを、このプロジェクト専用の「小 │
  │ 部屋」に閉じ込めるためです。ほかのプロジェクトとライ │
  │ ブラリのバージョンがぶつかる事故を防げます。「プロジ │
  │ ェクトごとの道具箱」のイメージです。                 │
  └──────────────────────────────────────────────────────┘
  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ (venv) が付いている間は、pip install した物がこのフ  │
  │ ォルダの venv の中だけに入る。VS Code も同じ道具箱を │
  │ 使うので、赤線が正しく出る。                         │
  └──────────────────────────────────────────────────────┘

─────────────────────────────────────────
  0-4. requirements.txt を作ってライブラリを入れる
─────────────────────────────────────────

フォルダの中に「requirements.txt」を作り、次の6行を書きます：

    discord.py>=2.3
    requests>=2.31
    beautifulsoup4>=4.12
    lxml>=5.0
    python-dotenv>=1.0
    tzdata

ターミナルで：

    pip install -r requirements.txt

「Successfully installed ...」と出ればOKです。

  各ライブラリの役割：
    discord.py      → Discordと話す(メッセージ送信・スラッシュコマンド)
    requests        → manabaのページを取りに行く(HTTP通信)
    beautifulsoup4  → 取ってきたHTMLから、課題の表を読み取る
    lxml            → beautifulsoup4 が使う、高速なHTML解析エンジン
    python-dotenv   → .env ファイルを読み込む
    tzdata          → 「日本時間」のデータ(Windowsには入っていないため必要)

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ Pythonには最初から入っている道具(標準ライブラリ)があ │
  │ りますが、Discordと話す機能や、HTMLを読み取る機能は  │
  │ 入っていません。pip は「世界中の人が作った道具を追加 │
  │ するアプリストア」で、requirements.txt は「このプロ  │
  │ ジェクトに必要な道具の買い物リスト」です。           │
  └──────────────────────────────────────────────────────┘
  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ コードの冒頭で「import discord」「import requests」  │
  │ などと書くだけで、それらの機能が使えるようになる。リ │
  │ ストがあるので、PCを替えても「pip install -r require │
  │ ments.txt」の1行で同じ環境を再現できる。             │
  └──────────────────────────────────────────────────────┘

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

─────────────────────────────────────────
  1-1. アプリケーションを作る
─────────────────────────────────────────

① https://discord.com/developers/applications を開く
② 右上「New Application」をクリック
③ 名前を入力(例：ManabaReminder)→「Create」

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ DiscordはBotを「アプリケーション」として管理していま │
  │ す。最初にDiscord側にアプリの枠を作らないと、Botとし │
  │ て認識してもらえません。イメージ：Botの「住民票」を  │
  │ 作る作業です。                                       │
  └──────────────────────────────────────────────────────┘
  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ DiscordがこのBotを正規のアプリとして認識する。次のス │
  │ テップで、トークン(合鍵)を発行できるようになる。     │
  └──────────────────────────────────────────────────────┘

─────────────────────────────────────────
  1-2. トークンを取得する
─────────────────────────────────────────

① 左メニュー「Bot」をクリック
② 「Reset Token」→ 確認ボタンを押す
③ 表示されたトークンを【コピーして安全な場所に保存】
   ※ トークンはパスワードと同じ。絶対に人に見せないこと！
   ※ 一度しか表示されないので、必ずコピーすること

④ 同じページの「Privileged Gateway Intents」は【全部オフのまま】
   (前回の指導書と違い、MESSAGE CONTENT などをオンにする必要はありません)

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ トークンは、Botが「自分はこのBotです」とDiscordに証  │
  │ 明するための合鍵です。Intents(特権インテント)は「Bot │
  │ がどんな情報まで受け取るか」の許可リストですが、この │
  │ Botはスラッシュコマンドと送信しか使わないので、メッ  │
  │ セージ本文もメンバー情報も要りません。必要最小限の権 │
  │ 限だけにするのが安全です。                           │
  └──────────────────────────────────────────────────────┘
  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ コードの最後の client.run(DISCORD_TOKEN) で、このト  │
  │ ークンを使ってBotがDiscordにログインできるようになる │
  │ 。                                                   │
  └──────────────────────────────────────────────────────┘

─────────────────────────────────────────
  1-3. BotをDiscordサーバーに招待する
─────────────────────────────────────────

(自分専用のサーバーを、先に作っておいてください。Discordの左側の
 「＋」ボタン →「オリジナルの作成」→「自分と友達のため」で作れます。
 通知用のテキストチャンネルも1つ作りましょう。)

① 左メニュー「OAuth2」→「URL Generator」
② 「SCOPES」で以下にチェック：
     ☑ bot
     ☑ applications.commands
③ 「BOT PERMISSIONS」で以下にチェック：
     ☑ View Channels(チャンネルを見る)
     ☑ Send Messages(メッセージを送る)
     ☑ Embed Links(埋め込みカードを使う)
④ 下に生成されたURLをコピーしてブラウザで開く
⑤ 自分のサーバーを選択 →「認証」

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ BotはDiscordのサーバーに「招待」しないと存在できませ │
  │ ん。このURLがBotを招待するための専用リンクです。     │
  │   bot                    → Botとしてサーバーに参加す │
  │ る                                                   │
  │   applications.commands  → /tasks などスラッシュコマ │
  │ ンドを使えるようにする                               │
  │ PERMISSIONSは「Botができること」の事前申告です。申告 │
  │ のない操作はDiscordが拒否してくれる、安全のための仕  │
  │ 組みです。                                           │
  └──────────────────────────────────────────────────────┘
  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ サーバーのメンバー一覧にBotが表示される。コマンドが  │
  │ そのサーバーで使えるようになり、指定チャンネルへの通 │
  │ 知も送れるようになる。                               │
  └──────────────────────────────────────────────────────┘

─────────────────────────────────────────
  1-4. 3つのIDを取得する
─────────────────────────────────────────

① Discordの「ユーザー設定」(歯車)→「詳細設定」→「開発者モード」をオン
② 通知用のチャンネルを右クリック →「チャンネルIDをコピー」
     → 【DISCORD_CHANNEL_ID】に使う
③ サーバー名を右クリック →「サーバーIDをコピー」
     → 【DISCORD_GUILD_ID】に使う
④ 自分のアイコンを右クリック →「ユーザーIDをコピー」
     → 【DISCORD_OWNER_ID】に使う

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ チャンネル名(#general など)は変更できますが、IDは変  │
  │ わりません。「どこに通知するか」「誰が操作できるか」 │
  │ は、数字のIDで指定するのが確実です。開発者モードをオ │
  │ ンにしないと、IDのコピーメニューが出ません。         │
  │   GUILD_ID → 指定するとスラッシュコマンドがすぐ使え  │
  │ るようになる                                         │
  │   OWNER_ID → 自分以外はコマンドを使えなくなり、通知  │
  │ で自分に@が付く                                      │
  └──────────────────────────────────────────────────────┘
  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ Botが「このチャンネルに送信せよ」と正確に指定できる  │
  │ 。IDが違うと通知が届かない、または意図しない場所に送 │
  │ られてしまう。                                       │
  └──────────────────────────────────────────────────────┘


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  PHASE 2：設定ファイルを作る(.env)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

フォルダの中に「.env」というファイルを作ります。
(VS Code の「新しいファイル」で、ファイル名を .env にする)

中身(=の前後にスペースを入れない、値を引用符で囲まない)：

    DISCORD_TOKEN=さっきコピーしたBotトークン
    DISCORD_CHANNEL_ID=通知チャンネルのID
    DISCORD_OWNER_ID=自分のユーザーID
    DISCORD_GUILD_ID=サーバーID

    MANABA_BASE_URL=https://cit.manaba.jp
    MANABA_USER=manabaのユーザID
    MANABA_PASSWORD=manabaのパスワード
    MANABA_SOURCE=library

    SYNC_INTERVAL_MIN=30
    DB_PATH=tasks.db
    QUIET_START_HOUR=0
    QUIET_END_HOUR=0
    REMIND_WITHIN_DAYS=7
    DEFAULT_DUE_HOUR=23
    DEFAULT_DUE_MINUTE=59

  ・MANABA_SOURCE=library  「未提出課題一覧」から取得(おすすめ)
                  course   各講義のページを巡回(予備。アクセス数が多い)
  ・SYNC_INTERVAL_MIN      manabaを見に行く間隔(分)。15未満にはなりません
  ・QUIET_START_HOUR/END   この時間帯はリマインドを送らない
                           (例：0と7なら、深夜0時〜7時は静か。両方0で無効)
  ・DEFAULT_DUE_HOUR/MINUTE  /add で時刻を省略したときの締切の時刻(既定 23:59)
  ・REMIND_WITHIN_DAYS     締切がこの日数より先の課題は、定期リマインドしない
                           (0で制限なし。新規検出の通知と /tasks には出る)

【重要】.env は絶対にGitHubなどに公開しないこと！
        (.gitignore に「.env」と書いておけば、Gitが無視してくれます)

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ トークンやパスワードをコードに直接書くと、コードを人 │
  │ に見せたときに一緒に漏れます。.env に分けておけば「  │
  │ コードは共有OK、秘密は非公開」にできます。python-dot │
  │ env が .env を読み取り、Pythonからはos.getenv("MANAB │
  │ A_USER") で取り出せます。                            │
  └──────────────────────────────────────────────────────┘
  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ Botを起動すると .env が自動で読み込まれ、設定がプロ  │
  │ グラムの中で使えるようになる。1行書き換えるだけで、  │
  │ 別のチャンネルや別の設定に切り替えられる。           │
  └──────────────────────────────────────────────────────┘

同じ場所に「.gitignore」も作り、次を書いておきましょう：

    .env
    tasks.db
    *.db
    debug/
    venv/
    .venv/
    __pycache__/
    .pytest_cache/

  PHASE 3：作る前に、設計を頭に入れよう
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

manaba_bot.py は約930行あります。いきなり全部を写すのではなく、
次の「3つの層」を意識しながら、上から順に書き進めます。

  [取得層] ManabaClient       manabaにログインしてHTMLを読み取る
       │                       (セクション3)
       ▼
  [保存層] SQLite + apply_sync 課題を記録し、新規/変更/提出済みを判定
       │                       (セクション4)
       ▼
  [通知層] Discord Bot         通知・定期実行・コマンド
                               (セクション5, 6)

ファイルの中は、次の7つのセクションに分かれています：

   1. 設定                       .env を読み込む
   2. データ型と日時の道具       課題の「箱」、日時の変換・整形
   3. manabaクライアント         ログインと一覧の読み取り(いちばん難しい)
   4. データベース               課題の保存と、差分の判定
   5. 表示の整形                 Discordに出すカードを作る
   6. Discord Bot本体            通知・定期実行・コマンド
   7. --check と起動             取得だけを試すモードと、起動処理

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ 取得と通知を直接つながず、必ずDBを間に挟んでいます。 │
  │ そのおかげで(1) manabaが一時的に落ちても通知は続く、 │
  │ (2) 前回との差分(新規・締切変更)が分かる、(3) 取得部 │
  │ 分だけを差し替えられる、という利点が生まれます。大き │
  │ なプログラムは「役割ごとに分ける」ほど読みやすく、壊 │

  4-11. 日付の読み取り(正規表現)
─────────────────────────────────────────

    DATE_RE = re.compile(r"(\d{4})[-/年]\s*(\d{1,2})[-/月]\s*(\d{1,2})日?\s*(\d{1,2})[:時]\s*(\d{2})")
    # /add 用。日付: 10/10 10-10 10月10日 1010(月日4桁) / 時刻: 18:30 18時30分 18時 1830 18
    USER_DATE_RE = re.compile(r"(\d{1,2})[/\-.月](\d{1,2})日?|(\d{2})(\d{2})")
    USER_TIME_RE = re.compile(r"(\d{1,2})[:時](\d{1,2})分?|(\d{1,2})時|(\d{2})(\d{2})|(\d{1,2})")


    def parse_dt(text: str) -> Optional[datetime]:
        m = DATE_RE.search(text or "")
        if not m:
            return None
        y, mo, d, h, mi = (int(x) for x in m.groups())
        try:
            return datetime(y, mo, d, h, mi, tzinfo=JST)
        except ValueError:
            return None

  ↑ 何をしているか：
    DATE_RE   → 「2026-10-08 23:59」の 年・月・日・時・分 を5つの括弧で取り出す型
                 (区切りは - / 年 月 日 時 : のどれでも読める)
    re.search → 文字列の中から型に合う部分を探す(なければ None)
    m.groups()→ 括弧の中身5つを文字列で取り出す
    datetime(..., tzinfo=JST) → 日本時間の日時を作る
    except ValueError → 2月30日のような存在しない日付は None を返す
    USER_DATE_RE / USER_TIME_RE → /add 用。人間が打つ短い日付・時刻の型(次のブロックで使う)

  4-12. /add 用の、人間が入力する日時の読み取り ★全角・短縮形に対応
─────────────────────────────────────────

    def parse_user_due(text: str) -> Optional[datetime]:
        """
        /add 用の締切の読み取り。全角でも半角でもよい。
          '2026-10-08 23:59'              年つき
          '10/8 23:59' '10月8日 18時' '1008 1830'   月日 + 時刻
          '1008' '10/8' '10月8日'          時刻を省略 → DEFAULT_DUE_HOUR:DEFAULT_DUE_MINUTE
        """
        t = unicodedata.normalize("NFKC", text or "").strip()    # 全角→半角('１０／１０ １０：００' → '10/10 10:00')
        dt = parse_dt(t)
        if dt:
            return dt
        parts = t.split()
        if len(parts) not in (1, 2):
            return None
        m = USER_DATE_RE.fullmatch(parts[0])
        if not m:
            return None
        month, day = (int(m.group(1)), int(m.group(2))) if m.group(1) else (int(m.group(3)), int(m.group(4)))
        hour, minute = DEFAULT_DUE_HOUR, DEFAULT_DUE_MINUTE
        if len(parts) == 2:
            tm = USER_TIME_RE.fullmatch(parts[1])
            if not tm:
                return None
            g = tm.groups()
            if g[0] is not None:
                hour, minute = int(g[0]), int(g[1])
            elif g[2] is not None:
                hour, minute = int(g[2]), 0
            elif g[3] is not None:
                hour, minute = int(g[3]), int(g[4])
            else:
                hour, minute = int(g[5]), 0
        now = datetime.now(JST)
        try:
            dt = datetime(now.year, month, day, hour, minute, tzinfo=JST)
            if dt < now - timedelta(days=1):          # 1日以上過去なら来年とみなす(12月に「1/5」と入れた場合など)
                dt = dt.replace(year=now.year + 1)
        except ValueError:                            # 13月・25時・存在しない日付
            return None
        return dt

  ↑ 何をしているか：
    unicodedata.normalize("NFKC", ...) → 全角の数字・記号・スペースを半角にそろえる(１０／１０ → 10/10)
    parse_dt を先に試す        → 「2026-10-08 23:59」のように年があれば、そのまま使う
    USER_DATE_RE / USER_TIME_RE → 日付(10/10・10月10日・1010)と、時刻(18:30・18時・1830・18)を読む
    時刻を省略したとき          → DEFAULT_DUE_HOUR:DEFAULT_DUE_MINUTE(既定 23:59)
    1日以上過去なら来年        → 12月に「1/5」と入れた場合の補正
    13月・25時・存在しない日付  → ValueError → None(読めない扱い)

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ 手入力は「考えなくてよい」ほど楽でないと、使わなくな │
  │ る。全角のままでも、「1010」だけでも通るようにして、 │
  │ 入力の手間を減らす。数字だけの入力は「月日」と決め(1 │
  │ 010=10月10日)、時刻は締切が多い夜に固定する(省略した │
  │ とき 23:59)。                                        │
  └──────────────────────────────────────────────────────┘

  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ /add で「1010」と打つだけで、10月10日 23:59の締切で  │
  │ 登録できる。「１０／１０ １０：００」のような全角で  │
  │ も、「1010 1830」のように時刻を付けても通る。読めな  │
  │ い入力は None になり、/add が入力の形を案内する。    │
  └──────────────────────────────────────────────────────┘

    def fmt_remaining(delta: timedelta) -> str:
        minutes = int(delta.total_seconds() // 60)
        if minutes < 0:
            return "期限切れ"
        days, rem = divmod(minutes, 1440)
        hours, mins = divmod(rem, 60)
        if days:
            return f"{days}日{hours}時間"
        if hours:
            return f"{hours}時間{mins}分"
        return f"{mins}分"

  ↑ 何をしているか：
    delta.total_seconds() // 60 → 残りを「分」にする
    マイナスなら               → 「期限切れ」
    divmod(minutes, 1440)      → 日と、その余りに分ける(1日=1440分)
    divmod(rem, 60)            → 余りを時間と分に分ける
    日があれば「N日N時間」、なければ「N時間N分」、それもなければ「N分」

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ 「残り何日」だけでは締切が近いときに粗すぎ、「何分」 │
  │ だけでは遠いときに読みにくい。残りの大きさに合わせて │
  │ 、見せる単位を変えている。                           │
  └──────────────────────────────────────────────────────┘

  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ 「あと2日3時間」「あと5時間12分」「あと40分」のよう  │
  │ に表示される。                                       │
  └──────────────────────────────────────────────────────┘

  4-21. 通信の部品(1秒あける・文字化け対策・GET/POST)

        # ---- 低レベルHTTP(1秒以上間隔をあける) ----
        def _throttle(self) -> None:
            wait = 1.0 - (time.time() - self._last_request)
            if wait > 0:
                time.sleep(wait)

        def _fix_encoding(self, r: requests.Response) -> requests.Response:
            if not r.encoding or r.encoding.lower() == "iso-8859-1":
                r.encoding = "utf-8"
            return r

        def _get(self, url: str) -> requests.Response:
            self._throttle()
            r = self.s.get(url, timeout=30)
            self._last_request = time.time()
            return self._fix_encoding(r)

        def _send_form(self, method: str, url: str, data: Dict[str, str]) -> requests.Response:
            self._throttle()
            if method.lower() == "get":
                r = self.s.get(url, params=data, timeout=30)
            else:
                r = self.s.post(url, data=data, timeout=30)
            self._last_request = time.time()
            return self._fix_encoding(r)

  ↑ 何をしているか：
    _throttle      → 前回のアクセスから1秒未満なら、足りない分だけ待つ
    _fix_encoding  → 文字コードが不明/ISO-8859-1 なら utf-8 にする(日本語の文字化け防止)
    _get           → throttle → GET → 時刻を記録 → 文字コードを直す
    _send_form     → フォーム送信。get なら params、post なら data で送る

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ サーバーに負担をかけないため、アクセスは必ず1秒以上  │
  │ あける。requestsは文字コードが書かれていないと ISO-8 │
  │ 859-1 と推測するので、日本語が化ける。それを防ぐ。通 │
  │ 信の細かい作法を1か所にまとめておくと、他の関数はす  │
  │ っきりする。                                         │
  └──────────────────────────────────────────────────────┘

  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ 以降の関数は self._get(url) と書くだけで、安全で文字 │
  │ 化けしない取得ができる。                             │
  └──────────────────────────────────────────────────────┘

                visible = [i for i in inputs

                if hidden and not visible:
                    return form
            return None

  ↑ 何をしているか：
    _looks_logged_in  → 「ログアウト」の文字や logout を含むリンクがあれば、ログイン済みの画面
    _login_form       → <input type="password"> を含む <form> を探す
    _auto_submit_form → hiddenの入力だけで、見える入力欄がないフォームを探す
                        (SSOなどで挟まる「自動で次へ進むページ」の特徴)
    @staticmethod     → self を使わない関数、という印

  ┌─ なぜやるの？ ───────────────────────────────────────┐

  │ requestsにはJavaScriptがないので、自分でフォームを見 │
  │ つけて送信する必要がある。「今どんな画面にいるか」を │

  4-24. フォームを「送信データ」に変換する関数
─────────────────────────────────────────

        @staticmethod
        def _form_payload(form, page_url: str, creds: Optional[Tuple[str, str]] = None):
            data: Dict[str, str] = {}
            last_text_name: Optional[str] = None
            for el in form.find_all(["input", "select", "textarea"]):
                name = el.get("name")
                if not name:
                    continue
                if el.name == "select":
                    opt = el.find("option", selected=True) or el.find("option")
                    data[name] = (opt.get("value", opt.get_text(strip=True)) if opt else "")
                    continue
                if el.name == "textarea":
                    data[name] = el.get_text()
                    continue
                typ = (el.get("type") or "text").lower()
                if typ in ("submit", "button", "image", "reset", "file"):
                    if typ == "submit" and name not in data:
                        data[name] = el.get("value", "")
                    continue
                if typ in ("checkbox", "radio"):
                    if el.has_attr("checked"):
                        data[name] = el.get("value", "on")
                    continue
                if typ == "password" and creds:
                    data[name] = creds[1]
                    if last_text_name:
                        data[last_text_name] = creds[0]
                    continue
                if typ == "hidden":
                    data[name] = el.get("value", "")
                    continue
                # text / email / tel など(ユーザIDの入力欄候補)
                data[name] = el.get("value", "")
                last_text_name = name
            action = urljoin(page_url, form.get("action") or page_url)
            method = (form.get("method") or "post").lower()
            return method, action, data

  ↑ 何をしているか：
    form.find_all(["input","select","textarea"]) → フォームの入力欄を全部見る
    hidden        → 画面に見えない値(CSRFトークンなど)。value をそのまま送る
    text系        → 「ユーザID欄の候補」として名前を覚えておく(last_text_name)
    password      → パスワードを入れ、同時に「直前のtext欄」にユーザIDを入れる
    submit        → ボタンの name と value も送る(必要なサイトがあるため)
    checkbox      → チェックされているものだけ送る
    urljoin(page_url, action) → 相対URLを、完全なURLに直す

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ ログインフォームには、画面に見えない隠し項目が入って │
  │ いることがある。ブラウザはそれも一緒に送っているので │
  │ 、IDとパスワードだけ送ると拒否されることがある。入力 │
  │ 欄の名前を決め打ちにせず、「パスワード欄の直前の入力 │
  │ 欄=ユーザID」と判断することで、画面の細かい違いに強  │
  │ くなる。                                             │
  └──────────────────────────────────────────────────────┘

  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ どんなログインフォームでも、「ブラウザが送るのと同じ │
  │ データ」を作れる。(前提：ユーザID欄が、パスワード欄  │
  │ より前に書かれていること)                            │
  └──────────────────────────────────────────────────────┘

  4-25. login ― ログイン処理の本体 ★重要
─────────────────────────────────────────

        def login(self) -> None:
            """ID/パスワードでログイン。資格情報の送信は1回だけ(連続失敗によるロック防止)。"""
            self.s.cookies.clear()
            self.logged_in = False
            r = self._get(f"{self.base}/ct/home")
            sent = False
            for step in range(8):
                soup = BeautifulSoup(r.text, "lxml")
                self._dump(f"login_step{step}", r.text)
                if not soup.find("input", attrs={"type": "password"}) and self._looks_logged_in(soup):
                    self.logged_in = True
                    return
                form = self._login_form(soup)
                if form is not None:
                    if sent:
                        raise LoginError("ログイン後もログインフォームが表示されました。"
                                         "ID/パスワードの誤り、または追加の認証があるかもしれません。")
                    method, action, data = self._form_payload(form, r.url, (self.user, self.password))
                    r = self._send_form(method, action, data)
                    sent = True
                    continue
                auto = self._auto_submit_form(soup)
                if auto is not None:
                    method, action, data = self._form_payload(auto, r.url)
                    r = self._send_form(method, action, data)
                    continue
                break
            raise LoginError("ログイン後のページを確認できませんでした。"
                             "`python manaba_bot.py --check --dump-html` で状況を確認してください。")

  ↑ 何をしているか：
    cookies.clear()       → いったん全部忘れる
    GET /ct/home          → 未ログインなら、自動でログイン画面に移る
    for step in range(8)  → 最大8回、次を繰り返す(無限ループ防止)
      ログイン済みの画面     → 成功。終了
      ログインフォームがある → すでに送信済みなら LoginError / 未送信なら送信
      自動送信フォームがある → そのまま送って次へ
      どれでもない           → break して LoginError
    sent = True           → 「ID/パスワードを送った」という記録

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ ★ ID/パスワードを送るのは1回だけ。間違った資格情報を │
  │ 何度も送ると、アカウントがロックされる恐れがあるので │
  │ 、2回目のログイン画面が出たら即座に諦める。無限ルー  │
  │ プにならないよう、回数の上限も設けている。           │
  └──────────────────────────────────────────────────────┘

  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ 成功すれば self.logged_in=True。失敗すれば、理由付き │
  │ の LoginError が出る。                               │
  └──────────────────────────────────────────────────────┘

        def parse_list_page(html: str, page_url: str, skip_done: bool = False) -> Tuple[List[Item], bool]:
            """
            課題一覧のHTMLから課題を取り出す。
            戻り値: (課題のリスト, 一覧ページとして解釈できたか)
            ※ 列の位置は固定せず、ヘッダー(th)の文言と日付の形式から判断する

        def fetch_courses(self) -> SyncData:
            """各コースの課題ページを巡回して取得(提出済みは除外。自動完了判定はしない)"""
            data = SyncData(authoritative=False)
            home = self.get_page(f"{self.base}/ct/home", "home")
            courses: Dict[str, str] = {}
            for a in BeautifulSoup(home.text, "lxml").find_all("a", href=True):

                if m and a.get_text(strip=True):
                    courses.setdefault(m.group(1), a.get_text(" ", strip=True))
            if not courses:
                raise ParseError("ホームからコース一覧を見つけられませんでした")

                            it.course = cname
                        data.items_by_kind[kind].extend(items)
                    except LoginError:
                        raise
                    except Exception as e:
                        data.errors.append(f"{cname}/{KIND_LABEL[kind]}: {e}")
            return data

    # 4. データベース (SQLite)
    # =============================================================================
    @contextmanager
    def db():
        conn = sqlite3.connect(DB_PATH)
        conn.row_factory = sqlite3.Row
        try:
            yield conn
            conn.commit()
        finally:
            conn.close()

  ↑ 何をしているか：
    sqlite3.connect(DB_PATH)       → データベースファイルを開く(なければ作る)
    conn.row_factory = sqlite3.Row → row["title"] のように、列名で取り出せる
    @contextmanager + yield        → with db() as c: と書ける道具を自作する
    conn.commit()                  → 変更を保存する(正常に終わったときだけ)
    finally: conn.close()          → エラーが起きても、必ず閉じる

  │ やcommit忘れが起きる。with にまとめれば、ブロックを  │
  │ 抜けるときに自動で後始末してくれる。                 │
  └──────────────────────────────────────────────────────┘

  4-41. collect_reminders ― 「今、通知すべき課題」を選ぶ

    def collect_reminders(now: datetime) -> List[sqlite3.Row]:
        out = []
        with db() as c:
            for row in c.execute("SELECT * FROM tasks WHERE done=0 AND due IS NOT NULL ORDER BY due ASC"):
                remaining = from_iso(row["due"]) - now
                if remaining.total_seconds() <= 0:
                    continue                      # 期限切れは通知しない
                if REMIND_WITHIN_DAYS and remaining > timedelta(days=REMIND_WITHIN_DAYS):
                    continue                      # 締切がまだ遠い課題は、リマインドしない
                interval = timedelta(hours=interval_for(remaining.total_seconds() / 3600))
                last = from_iso(row["last_notified_at"])
                if last is None or now - last >= interval - timedelta(minutes=1):
                    out.append(row)
        return out

  ↑ 何をしているか：
    remaining <= 0 → 期限切れは通知しない
    remaining > REMIND_WITHIN_DAYS日 → 締切がまだ遠い課題は通知しない(関係のある課題に絞る)
    interval = interval_for(残り時間)  → 今の残り時間での間隔
    last is None  → 一度も通知していなければ対象
    now - last >= interval - 1分 → 前回の通知から間隔以上たっていれば対象

  ┌─ なぜやるの？ ───────────────────────────────────────┐
  │ 5分おきに全課題を確認しても、毎回通知したら迷惑。「  │
  │ 前回から間隔以上たった」ものだけを選ぶ。「-1分」は、 │
  │ 5分おきの確認の誤差で1回分飛ばされないための余裕。   │
  └──────────────────────────────────────────────────────┘

  ┌─ これをするとどうなる？ ─────────────────────────────┐
  │ 対象の課題のリストが返る。remind_loop が、これをまと │
  │ めて1通で送る。                                      │
  └──────────────────────────────────────────────────────┘

        hours = (soonest - now).total_seconds() / 3600
        return 0xE74C3C if hours < 24 else 0xF39C12 if hours < 72 else 0x2ECC71

        out = []

    @tree.command(name="add", description="課題を手入力で追加します(manaba以外の予定用)")
    @app_commands.describe(title="課題名", due="締切 例: 1010(時刻省略) / 10/10 18:00 / 1010 1830 / 10月10日 18時", course="科目名(任意)")
    async def cmd_add(interaction: discord.Interaction, title: str, due: str, course: str = ""):
        dt = parse_user_due(due)
        if dt is None:
            await interaction.response.send_message(
                f"締切を読み取れませんでした。`1010`(時刻は{DEFAULT_DUE_HOUR:02d}:{DEFAULT_DUE_MINUTE:02d}になります)・"

                ephemeral=True)
            return
        now_s = iso(datetime.now(JST))
        tid = f"manual:{uuid.uuid4().hex[:8]}"

            # last_notified_at は None(未通知)にしておく → 追加後、最初の確認(5分以内)でリマインドが届く。

            c.execute("INSERT INTO tasks(id,source,kind,title,course,url,due,done,last_notified_at,missing_count,"

                      (tid, "manual", None, title, course, None, iso(dt), None, now_s, now_s))
        await interaction.response.send_message(f"➕ 追加しました: {title}(締切 {fmt_due(dt)})")

  ↑ 何をしているか：

    # 7. 動作確認モード (--check) と起動
    # =============================================================================
    def run_check(dump: bool) -> int:
        if not (MANABA_USER and MANABA_PASSWORD):
            print("`.env` に MANABA_USER と MANABA_PASSWORD を設定してください。")
            return 1
        m = ManabaClient(BASE_URL, MANABA_USER, MANABA_PASSWORD, dump=dump)
        print(f"ベースURL: {BASE_URL} / 取得方式: {SOURCE_MODE}")
        try:
            m.login()
            print("✅ ログイン成功")
            data = m.fetch()
        except (LoginError, ParseError) as e:
            print(f"❌ {e}")
            if not dump:
                print("→ `--dump-html` を付けて再実行すると、HTMLを ./debug に保存します。")
            return 2
        now = datetime.now(JST)
        for kind, items in data.items_by_kind.items():
            print(f"\n■ {KIND_LABEL[kind]}: {len(items)}件")
            for it in sorted(items, key=lambda i: (i.due is None, i.due)):
                print(f"  - {it.course} | {it.title} | 締切 {fmt_due(it.due)}"
                      + (f" (あと{fmt_remaining(it.due - now)})" if it.due and it.due > now else ""))
        for e in data.errors:
            print(f"⚠️ {e}")
        if dump:
            print(f"\nHTMLを {DEBUG_DIR.resolve()} に保存しました(個人情報を含むので、共有前に氏名などを伏せてください)。")
        return 0

  ↑ 何をしているか：
    MANABA_USER/PASSWORD がなければ案内して終了
    m.login() → 「✅ ログイン成功」
    m.fetch() → 取得して、種類ごとに 科目 | タイトル | 締切 を表示
    LoginError / ParseError → 理由を表示。dump なら、HTMLの保存先も案内
    戻り値の数字 → 終了コード(0=成功 / 1,2=失敗)

  │ 「うまく動かない」とき、原因がmanaba側かDiscord側か  │
  │ 分からないと、直せない。取得だけを切り離して試せれば │
  │ 、原因を切り分けられる。                             │
  └──────────────────────────────────────────────────────┘

  PHASE 8：Pythonの基礎知識メモ(つまずいたとき用)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ インデント(字下げ)
  Pythonではインデントがコードの構造を決める。スペース4つで統一する。

    if x > 0:
        print("正の数")   ← ifの中(スペース4つ)
    print("ここはifの外")

■ def(関数)とclass(クラス)
    def add(a, b):          「処理」に名前を付けたもの
        return a + b

    class Item:             「データと処理をまとめた箱」の設計図
        def __init__(self): 作った瞬間に動く準備処理

■ 型ヒント
    def f(x: int) -> str:   「xはint、戻り値はstr」という目印
    Optional[datetime]      「日時、またはNone」
    List[Item]              「Itemのリスト」
  型ヒントは実行には影響しません(読む人とエディタへの説明です)。

■ dataclass
  「データを入れるだけの箱」を短く書く仕組み。
    @dataclass
    class Item:
        id: str
        title: str
  と書くと、Item(id="a", title="b") で作れる。

■ 正規表現(re)
  文字列から「型」に合う部分を取り出す道具。
    (\d+)    数字が1個以上。()で囲むと「取り出したい部分」になる
    |        または      例 (query|survey|report)
    \s*      空白が0個以上
  re.search(型, 文字列) → 見つかれば Match、なければ None
  m.groups() → 括弧の中身をまとめて取り出す

■ try / except(エラー処理)
    try:
        危険な処理
    except ValueError:
        失敗したときの処理
  自作の例外(class LoginError(Exception))を作れば、失敗の種類で処理を
  分けられる。

■ with文
  開いて、処理が終わったら自動で閉じる。
    with db() as c:
        c.execute(...)

■ デコレータ(@で始まる行)
  関数に役割を与えるラベル。
    @tree.command(name="tasks")    → スラッシュコマンドとして登録
    @tasks.loop(minutes=30)        → 30分おきに繰り返す
    @staticmethod                  → selfを使わない関数

■ async / await
  Discordのやり取りなど「待ち時間が多い処理」に使う。await は
  「終わるまで待つ(その間、他の処理を進めてよい)」という意味。
    async def f():
        await ch.send("こんにちは")
  通常の重い処理(requestsなど)は、そのままだとBot全体が止まるので
    await asyncio.to_thread(関数)
  で別スレッドに逃がす。

■ f文字列
    name = "太郎"
    print(f"こんにちは、{name}さん")        → こんにちは、太郎さん
    print(f"{dt:%H:%M}")                     → 23:59(書式の指定)

■ BeautifulSoup(HTMLの読み取り)
    soup = BeautifulSoup(html, "lxml")
    soup.find_all("a")                    すべてのリンク
    a.get("href")                         属性の値
    a.get_text(" ", strip=True)           中の文字

■ SQLiteの「?」
    c.execute("SELECT * FROM tasks WHERE id=?", (task_id,))
  値は文字列に直接埋め込まず、「?」にして後から渡す(安全のため)。
  値が1つでも (task_id,) のようにタプルで渡す。

  付録A：設計の「なぜ」(面接やガクチカで話せるように)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

 1) 取得と通知の間にDBを置いた
    → 差分(新規・締切変更・提出済み)が分かる。manabaが不調でも動く。

 2) ID/パスワードを送るのは1回だけ
    → 失敗の繰り返しによるアカウントロックを避ける。さらに、3回連続
      の失敗で自動同期自体を止める(二重の安全装置)。

 3) 表の列の位置を決め打ちせず、見出しと日付の形式で解析する
    → 画面の細かい変更に強い。

 4) 「解釈できたか」を返し、失敗と0件を区別する
    → 解析の失敗で、全課題が誤って「提出済み」になる事故を防ぐ。

 5) 取得に成功した種類だけDBを更新する
    → 一部の失敗が、他のデータに波及しない。

 6) 一覧から2回続けて消えたら自動完了
    → 一時的な取得ミスによる、誤判定を避ける。

 7) アクセスは1秒以上あけ、同期は最短15分
    → 相手のサーバーへの配慮と、ブロックされるリスクの低減。

 8) 重い処理は asyncio.to_thread で別スレッドへ
    → Botの接続維持(ハートビート)を妨げない。

 9) 通知は「送れたときだけ」記録する
    → 送信失敗で、リマインドが抜け落ちるのを防ぐ。

10) 秘密情報は .env に分離し、.gitignore で除外
    → コードを公開しても、パスワードやトークンは漏れない。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

「--check」でうまく取れなかったときの手順です。

 1) HTMLを保存する
      python manaba_bot.py --check --dump-html
    debug/ フォルダに、次のようなファイルができます：
      login_step0.html      最初に開いたページ(ログイン画面)
      login_step1.html ...  ログイン後に進んだページ
      home.html             ホーム画面
      library_query.html    未提出の小テスト一覧
      library_survey.html   未提出のアンケート一覧
      library_report.html   未提出のレポート一覧

 2) ログインで失敗するとき → login_step0.html を開く
      ・<form> の中に、type="password" の入力欄があるか
      ・ユーザID欄(type="text")が、パスワード欄より前にあるか
      ・ログイン後に、別の画面(同意・追加認証)が出ていないか
        (login_step1.html 以降を見る)

 3) 課題が取れないとき → library_report.html などを開く
      ・<table> があるか。見出し(<th>)に「タイトル」「受付終了日時」
        などがあるか
      ・課題のリンクが course_数字_report_数字 の形か(href を確認)
      ・「未提出の○○はありません」という文があるか
      ・URLが違う場合は、ホームの「未提出課題一覧」のリンクを調べる

 4) HTMLを誰かに見せる(相談・AIに貼る)ときは、必ず先に伏せる：
      ・氏名、学籍番号、メールアドレス
      ・必要なら、科目名や教員名
      ・Cookie、トークンのような長い英数字
    (debug/ は .gitignore に入っているので、GitHubには上がりません)

 5) 調整する場所

      ・表の読み取り  → ManabaClient.parse_list_page
      ・URL           → fetch_library の urls

      from manaba_bot import ManabaClient
      html = open("debug/library_report.html", encoding="utf-8").read()
      print(ManabaClient.parse_list_page(html, "https://cit.manaba.jp/ct/"))

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

 Q1. なぜ ID/パスワードの送信を1回に制限している？
 A1. 間違った資格情報を繰り返し送ると、アカウントがロックされる恐れが
     あるため。2回目のログイン画面が出たら、失敗とみなして諦める。

 Q2. parse_list_page が (items, ok) の2つを返すのはなぜ？
 A2. 「本当に0件」と「解析できなかった」を区別するため。区別しないと、
     解析に失敗した回に全課題が「一覧から消えた」扱いになり、誤って
     提出済みとして自動完了される。

 Q3. 一覧から消えた課題を、すぐ完了にしないのはなぜ？
 A3. 取得が一時的に不完全だった場合の誤判定を避けるため。2回連続で
     消えたときだけ完了とする(missing_count)。

 Q4. requests を asyncio.to_thread で包んでいる理由は？
 A4. requests は通信中にプログラム全体を止めるため。そのままだと、
     Discordとの接続維持が妨げられ、切断される恐れがある。

 Q5. 締切が変更されたとき last_notified_at を NULL に戻すのはなぜ？
 A5. 次のリマインド判定で「未通知」とみなされ、新しい締切に合わせて
     すぐ通知し直されるから。

 Q6. SQLで値を「?」にして渡す理由は？
 A6. SQLインジェクション(入力によってSQL文が書き換えられる攻撃)を
     防ぐため。

 Q7. 取得に失敗した種類を items_by_kind に入れないと、何が良い？
 A7. apply_sync がその種類のDBに触らないので、一部の失敗が、他の
     データや自動完了の判定に影響しない。

 Q8. post が True/False を返すメリットは？
 A8. 送信に成功したときだけ mark_notified できる。失敗した通知を
     「済み」にしてしまい、リマインドが抜けるのを防げる。
